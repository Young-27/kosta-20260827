# 동적 위임 오케스트레이션

관련 커맨드: [`/dispatch`](../../.claude/commands/dispatch.md), [`dispatcher`](../../.claude/commands/dispatcher.md)

## 흐름

```text
사용자 요청 → dispatcher의 담당 판정 → 선택된 담당 에이전트 1명
```

`dispatcher`는 구현하지 않고 요청의 성격을 읽어 담당자와 근거를 두 줄로 출력한다.

| 요청 성격 | 담당 |
|---|---|
| 새 기능·동작 변경 | `implementer` |
| 테스트만 필요 | `tester` |
| 판단·평가만 필요 | `reviewer` |
| 요구가 모호함 | `requirements-analyst` |

담당이 정해지면 사용자의 원문 과제를 선택된 담당자 하나에게만 전달한다. 담당자의 역할 밖에 있는 추가 지시를 붙이지 않는다.

## 가드레일

- 다른 에이전트 호출을 지시하지 않는다.
- 테스트 담당 지정, 리뷰, 재작업, 병렬 처리, 파이프라인 처리를 추가하지 않는다.
- 결과가 부족해도 다른 담당자에게 재위임하지 않는다.
- 담당자의 결과를 받은 뒤 추가 작업을 지시하지 않고 결과를 전달한다.
- 전체 호출 수는 `dispatcher` 1회와 선택된 담당자 1회, 최대 2회다.

즉, `/dispatch`는 전체 개발 프로세스를 자동으로 확장하는 명령이 아니라, 요청에 맞는 단일 담당자를 라우팅하는 방식이다.

## 사용 시점

작업 성격에 맞는 전문가 한 명에게 맡기면 충분한 요청에 사용한다. 분석부터 리뷰까지 연결하거나 반복 수정이 필요하면 [순차](./sequential.md) 또는 [핸드오프](./handoff.md)를 사용한다.
